1. How HTTP Applications Preserve State Across Request–Response Cycles

HTTP is a stateless protocol, meaning each request–response cycle is independent and the server does not inherently remember previous interactions. To preserve state across multiple requests—especially for user authentication and session management—web applications use several mechanisms. The most common are cookies and server-side sessions. When a user logs in, the server creates a session record (stored in a database, cache, or file) containing data such as the user ID, login time, and permissions. It then sends a session ID to the client as a cookie. On every subsequent request, the browser automatically includes this cookie, allowing the server to look up the session and reconstruct the user's state. Token-based approaches such as JSON Web Tokens (JWTs) store state on the client side; the token is signed by the server and sent with each request, and the server verifies its signature. Django specifically uses its django.contrib.sessions framework, which stores session data server-side and only exposes an opaque session key to the client, providing strong security. CSRF tokens are also used to ensure requests originate from trusted sources. Together, these techniques let stateless HTTP applications simulate a continuous, stateful user experience.

2. Performing Django Database Migrations to MariaDB

Migrating a Django project from SQLite to a server-based relational database such as MariaDB requires several steps. First, install the database driver: pip install mysqlclient (or mariadb), and ensure the MariaDB server is running and a database plus user have been created (e.g., CREATE DATABASE sticky_notes; and a user with GRANT ALL privileges). Next, update the DATABASES setting in settings.py to use django.db.backends.mysql with the database name, user, password, host, and port. Because Django's ORM is database-agnostic, the same models work across backends, but migrations must be regenerated if switching from an existing SQLite database. Run python manage.py makemigrations to create migration files, then python manage.py migrate to apply them to MariaDB—this creates the schema. For existing data, use python manage.py dumpdata from the old database and python manage.py loaddata into the new one, or the --database flag to target a specific alias. Common issues include utf8mb4 charset configuration, STRICT_TRANS_TABLES SQL mode, and timezone handling (USE_TZ = True). Finally, test the connection with python manage.py dbshell and verify CRUD operations.
